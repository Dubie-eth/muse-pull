Cardigan (executor)

runs natively — no api key needed
cardigan — flock decision · native
always on
the executor needs full tool access and 1–2 block speed. an api round-trip would add fatal latency, so cardigan stays on the native model.
how key storage works. when you provide a key, it goes directly into secure vault storage through an encrypted entry card. the flock's model router reads keys at runtime and sends them only to the provider's api — never to logs, files, or chat. to rotate a key, just provide a new one; it replaces the old.
